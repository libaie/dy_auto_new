模型配置中心 — 完整设计方案

独立数据模型 + CRUD 页面 + PipelineLayerConfig 联动

1. 数据模型：AIModel 表

一张表 + type-specific JSON config 字段，不拆多表。provider 切换时前端动态显隐字段。

class AIModel(Base):
    __tablename__ = "ai_models"

    id              = UUID PK
    name            = String(100)    # 显示名, 如 "DeepSeek V3"
    model_type      = String(20)     # llm | image | video | tts | audit
    provider        = String(30)     # deepseek | openai | seedance | kling | ...
    base_url        = String(300)    # API 端点
    api_key         = String(500)    # 加密存储
    api_secret      = String(500)    # 加密存储 (Kling 双钥等)
    model_name      = String(100)    # deepseek-chat / doubao-seedance-2.0 / ...
    config_json     = JSON            # 各类型专属字段
    enabled         = Boolean         # 是否启用
    sort_order      = Integer
    created_at      = DateTime

# config_json 内容示例:
# llm:    {"thinking_enabled":true, "thinking_budget":8192, "max_tokens":4096, "temperature":0.7}
# image:  {"default_size":"1024x1024", "default_quality":"hd"}
# video:  {"default_resolution":"1080p", "default_duration":5, "default_aspect_ratio":"9:16"}
# tts:    {"default_voice":"zh-CN-XiaoxiaoNeural", "default_language":"zh-CN", "default_speed":1.0}
# audit:  {"audit_mode":"single"}

3. 与 PipelineLayerConfig 联动

PipelineLayerConfig 每层的模型下拉选项从 AIModel 表动态拉取，不再从 reference_data 查。

GET /api/ai-models?model_type=llm&enabled=true
→ [{ id, name, provider, model_name, ... }]

PipelineLayerConfig 直接展示返回的模型列表，用户选的模型 ID
随 pipeline start 请求下发 → backend 根据 model_id 查 config 调用对应 API

4. API 设计

GET    /api/ai-models                    # 列表, ?model_type=llm 过滤
GET    /api/ai-models/{id}               # 详情 (含解密 api_key)
POST   /api/ai-models                    # 新增
PUT    /api/ai-models/{id}               # 更新
DELETE /api/ai-models/{id}               # 删除
GET    /api/ai-models/options            # 供 PipelineLayerConfig 拉取
                                          # → [{id, name, model_type, provider}]

替代现有 ai_config.py 的 SystemSetting 键值对方案。旧 /api/ai-config/models 保留兼容。
