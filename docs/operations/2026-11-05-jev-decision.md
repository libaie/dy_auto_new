# Jev 决策模型接入与使用

## 这次替换的范围

决策模型使用 `typesafe-ai/jev`，服务端直接请求：

```text
POST https://ai-gateway.vercel.sh/typesafe/v1/systemone
```

| 功能 | 启用 Jev 后的处理 |
|---|---|
| 评论评分、意图识别、机器人/同行排除 | Jev 结构化判断 |
| 内容是否与行业或关键词矩阵相关 | 明确的本地规则先判断，需要模型时使用 Jev |
| 采集、只关注/私信模式中的线索资格判断 | 只执行决策，不额外生成评论回复文案 |
| 评论回复、私信、视频文案 | 继续使用现有生成模型 |
| 控件定位、屏幕坐标换算、发送确认 | 继续使用多分辨率定位和确认机制 |

Jev 使用 System One 原生接口，请求字段为 `model/state/questions`。它返回选择、评分和概率；不要把它填入原先的 Chat Completions 文案生成模型地址。API Key 只在服务端读取，手机端调用带设备认证的 `/api/device/decision-proxy`。

## 配置方法

### 方法一：服务端环境变量

在部署实际使用的私有 `.env` 中设置以下字段，并将密钥填入 `DECISION_API_KEY`。保留部署已有的其他环境变量。

```dotenv
DECISION_ENABLED=true
DECISION_MODEL=typesafe-ai/jev
DECISION_API_URL=https://ai-gateway.vercel.sh/typesafe/v1/systemone
DECISION_API_KEY=
DECISION_MIN_CONFIDENCE=0.5
DECISION_MIN_PROBABILITY=0.75
```

`DECISION_API_KEY` 上面故意留空，请在自己的服务器私有配置中填写。不要提交含真实密钥的文件。修改环境变量后重启后端进程。若数据库已经保存同名 `decision_*` 设置，数据库值优先；可以通过管理页修改已有配置。

### 方法二：管理页

进入管理后台 **AI 配置 → Jev 决策模型**（`/settings`），打开“启用 Jev 决策”，填入 AI Gateway API Key，点击页面底部“保存设置”。

通过管理页保存密钥前，服务端必须配置私有、随机的 `ENCRYPTION_KEY`。已有部署必须保留原加密密钥，修改它会影响现有加密数据的读取。新部署可自行生成随机值，例如 `python -c "import secrets; print(secrets.token_urlsafe(32))"`，然后写入私有环境配置并重启后端。

管理页保存的决策 API Key 使用服务端加密模块保存；读取设置时只返回掩码。输入框留空表示保留现有值；关闭 Jev 不会清除密钥。管理页展示的是数据库与环境变量合并后的有效配置。

配对、注册和轮询都会向手机下发决策开关、模型名和门槛。修改管理页配置后，已经升级脚本的手机在下一次轮询时应用，包括显式关闭开关。手机不会接收到网关密钥。

启动时，手机先取得服务端有效配置并完成选择器、模板初始化，再执行推送任务。首次注册或轮询失败时，任务等待配置并继续尝试同步；不会仅凭本地默认值使用旧判断。与旧服务端兼容时，成功取得的完整配置若没有决策字段，会明确按旧流程处理。

## 评分与不确定结果

Jev 原生 `score` 是有序等级的位置，范围为 `0` 到 `等级数 - 1`，可能带小数。手机端换算为：

```text
百分制分数 = 原生 score / (等级数 - 1) × 100
```

业务仍按原有门槛处理：低于 40 为 low，40–69 为 medium，70 及以上为 high。行业模板中的评分规则、意图候选和语义上下文继续参与判断，不限于某一个行业。

普通采集和分享链接采集均使用当前任务选择的提示词模板。未选择模板的新任务恢复默认配置，避免继承上一任务的行业覆盖内容。

两个门槛含义不同：

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `DECISION_MIN_CONFIDENCE` | 0.5 | score 类型判断（评论评分、紧迫程度）的原生 confidence |
| `DECISION_MIN_PROBABILITY` | 0.75 | 意图等选择题所选项概率、相关性判断和布尔排除项判断所需的概率 |

`noul=0.02` 表示某个判断明显为假；它不代表该结果只有 2% 的可信度。排除项判断会区分“明确为假”和“真假不确定”。已经明确判定为机器人或同行的对象不会被当成高分线索继续采集。

开启 Jev 后，请求超时、认证失败、缺少必需答案、结果类型错误、概率越界或关键判断不确定，都会跳过当前判断，不会悄悄改用另一模型。关闭 Jev 时恢复原有判断逻辑。相关性无法确认时不互动。

初始门槛是保守的业务默认值，不是对实际准确率的保证。上线后应使用已人工标注的行业样本观察漏判与误判，再调整门槛。

## 更新顺序

1. 部署包含本次变更的后端与前端。
2. 更新手机完整 `device/` 目录并重启 AutoJS6；新增的核心决策模块必须一起更新。仅刷新管理网页不会升级手机脚本。
3. 在后端环境变量或管理页配置决策 Key 并开启 Jev。
4. 保留原生成模型的配置，以便生成实际需要发送的回复与私信。
5. 先在少量任务上检查决策与发送确认日志，再扩大任务范围。

本次代码更新不代表已部署到生产服务器或已替换手机正在运行的脚本。草稿 PR 的合并、后端部署和手机脚本升级是独立步骤。
