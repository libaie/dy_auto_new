### 几项兼容性决定

- 指定手机的关键词批量任务使用直接任务队列，返回 `mode=direct`；不指定手机的批量任务继续使用通道。定向批量不自动变成可整体暂停/编辑的通道。
- 目标设备约束存放在服务端保留参数中，不需要数据库结构迁移。任务 API、设备任务、链详情和链 WebSocket 消息均剥离该内部字段。
- Jev 继续只负责判断；回复/私信文案继续走已有生成模型。取消、空结果或请求异常不会触发新的发送。
- 主设备密钥保留原有全设备访问能力。生产手机应继续使用各自配对凭据，本轮没有把兼容主密钥变成普通手机身份。
- 取消是协作式退出：阻止后续动作，但无法撤销在取消到达前已经完成的点击、发送或平台侧操作。

## 脚本更新与回退

从仓库根目录运行：

```bash
python tools/pack_device.py --output device-script.zip
```

该命令使用标准库，打包实际运行文件并生成 `device-update.json`。服务端会拒绝无清单、文件摘要不符、路径异常或缺失静态本地依赖的 ZIP，返回 HTTP 400，且不推进版本。

设备更新将新文件复制到项目内独立 release 目录，复核后以同目录入口替换作为启用点。入口元数据同时记录版本，版本侧车文件只保留兼容用途。原根模块和上一入口保留；连续升级固定项目根目录，避免把新版本嵌套到上一 release 中。正常应用新版本仍需重启脚本，后台页面刷新不等于手机升级。

首次采用这套更新器时，先完整更新手机 `device/` 目录并重启，再试验新的 ZIP 流程。旧更新器不会因为后端升级而自动获得新的校验和回退保证。

## 仍存在的限制与验收缺口

1. **跨用户重复线索的独立保存尚未实现。** `CollectedUser.douyin_id` 仍是全局唯一。本轮已阻止归属覆盖，但第二位管理用户不能独立拥有同一抖音 ID 的另一份资料。完整支持需要设计按所有者去重或独立采集关系，并做有备份的数据迁移；本轮没有破坏性改表。
2. **带历史引用的设备硬删除暂不支持。** 统计事件、链实例和通道项仍有设备外键。本轮用 HTTP 409 阻止不完整删除，保留连接与历史数据；没有为绕过外键而删掉历史统计或任务。要支持删除这类手机，需要明确保留期限和历史归属并实现归档/软删除迁移。无这些引用的设备仍可正常删除和重新配对。
3. **真机行为尚未验收。** Node 回归不能证明 AutoJS6 Java 桥接、文件原子重命名、实际应用启动、输入法遮挡、无障碍层级、横竖屏和不同厂商窗口信息完全一致。尤其新的脚本入口切换必须先单机试验，不能直接宣称所有手机可用。
4. **生产数据库并发行为未验证。** 本轮后端回归使用隔离 SQLite；设备删除回归专门启用了外键约束。实际部署若使用 MySQL，多设备同时领取、取消/重试和删除设备需要在预发布环境验证；没有对生产数据执行迁移或压力测试。
5. **模型的业务准确率没有由软件测试证明。** 本轮检查协议、阈值、异常和动作边界。不同业务行业的误判/漏判需要人工标注样本评估。

## 建议的验收顺序

1. 部署后端与前端到预发布环境，确认设置读取失败时无法保存、Jev 开关修改不改变原生成配置。
2. 完整更新一台测试手机，执行少量明确目标任务，核对实际登录账号和后台绑定账号。
3. 分别在排队后、AI 请求中、私信序列中取消；移除并重新配对设备，确认旧会话不继续发送、不使新会话退出。
4. 在 720×1600、1080×2340/2400、1440×3200 等实际设备中检查语义定位、键盘遮挡、页面切换及模板同步。模拟测试覆盖这些尺寸不等于所有型号都已实测。
5. 测试正确更新包、缺文件包、写入失败及连续两次升级；每次重启确认版本、主入口和旧版本回退可用。
6. 两台手机验证定向任务失败/超时仍留在目标手机，自动任务可正常重派；检查统计、私信展示和跨用户数据冲突提示。删除有历史引用的设备应得到明确拒绝且仍保持连接；无引用设备重新配给其他用户后不得修改前任用户的记录。

满足这些条件后，再决定将草稿 PR 转为可合并并逐步更新其他手机。
