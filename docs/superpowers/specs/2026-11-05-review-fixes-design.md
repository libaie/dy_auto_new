# 审查问题修复设计

## 授权与目标

用户在收到针对 `802fec68abbfea2bb5eb25181ac5feef392ee2cd` 的十五项问题审查后要求“请进行修复”。本次完成这些缺陷的修复、回归测试和可审核的分支交付。维持 FastAPI / SQLAlchemy、Vue 3 和 AutoJS6 的现有架构。

## 约束

- 设备端保持 AutoJS6 / Rhino ES5.1：只能使用 var、function 和回调，不引入 Promise、箭头函数或 ES6 模块。
- 服务端继续使用 `bj_now()` 的 UTC+8 naive datetime。
- 保留已发布的迁移历史，以新增合并迁移收敛分支。
- 不调用真实付费模型服务，不修改线上数据库，不直接合并 main。
- 权限变更允许管理员管理全局资源，普通用户只能访问和操作其所有的资源。
- 修复后保持公开 API 的现有响应结构；明确错误情况可以返回 403/404/409。
- 只改变确认缺陷及其必要关联行为，不重构无关业务。

## 采用方式

采用按缺陷边界修复并增加行为回归测试的方式。完整架构重写会扩大回归风险；只调整测试预期不能修复已复现的业务故障。本次保留现有服务与路由结构，对必要的公共状态或授权逻辑使用小型辅助模块。

## 修复要求

1. 任务详情、取消、单条/批量删除必须校验所有权；批量操作在发生任何修改前验证整批权限。设备配对审批校验角色和设备已有归属；WebSocket 对管理员和资源所有者正确分发，默认广播不能泄露给其他普通用户。
2. Alembic 只保留一个 head；空库升级与已有 head 升级均成功；必要迁移失败不得被吞掉。SQLite PRAGMA 只注册到 SQLite。
3. 暂停通道保留待处理工作。恢复后原有项目可继续领取；取消仍为终止行为。处理运行中任务时防止旧回报覆盖新领取。
4. 服务端和设备端使用一致的任务期限：养号按照配置 duration（分钟）加缓冲，至少 10 分钟；服务端可保留配置的更大最低期限。直接任务与通道任务分别恢复且有有限重试。
5. 真实生产 worker 回收过期租约；保留已提交 provider 任务的关联，拒绝旧租约回写；队列剩余量不能掩盖卡住的租约。
6. 图像任务在调用上游前必须原子取得执行权，阻止同一任务并发重复提交；使用稳定外部任务 ID，并防止迟到响应覆盖新执行。
7. 设备执行器与 handler 消除循环依赖，实际模块加载顺序可运行。
8. 直接队列可继续检查前十条之后的可执行任务，领取时拒绝非 active 账号。
9. 任务删除在外键开启时正确处理 StatsEvent 等关联，保留独立的累计统计语义。
10. 通道离线/超时回收累计同一工作项的尝试次数，遵循重试上限。
11. `-1` 全量搜索执行实际处理，并以取消、结果耗尽或任务期限为边界。
12. 离线结果队列跳过/隔离永久失败，继续上报有效项目；临时失败在正常通信时仍可重试，避免递归刷新。
13. 审核证据保留未识别英文及标识符，未知翻译不得冒充无证据。
14. 修正缺失的测试依赖、新 API mock，以及已确认过时的测试契约；关键数据库回归使用开启外键的真实 SQLAlchemy 操作。

## 验证与范围

每个行为缺陷先建立失败回归，再做最小修复。完成后运行后端完整 pytest、前端完整 Vitest、生产构建、设备 Node 测试和迁移升级测试。Node 测试不替代 AutoJS 真机验证；没有真实 MySQL 或 provider 的行为必须如实标明验证范围。
